# Repository Instructions

This repository is one plugin, `vibecode` (Structured Vibe Code), for Claude Code and Codex. The repository is also its own single-plugin marketplace.

## Commands the plugin exposes

| Command | Effect |
|---|---|
| `/vibecode` | first run: create `.vibecoding/`, `STRUCTURE.md`, `.decisions.jsonl`, gitignore entry and turn active mode on; later: turn it on, or show status when already on |
| `/vibecode off` | active mode off, stored in `.vibecoding/state.json` |
| `/vibecode terse` | toggle the compressed voice flag in the same file (on by default with active mode) |
| `/vibecode understand` | map repository and history into `.vibecoding/understanding.md` |
| `/vibecode allow [<scope> --until <date>]` | list grants, or grant scoped, dated permission for autonomous implementation |

`commands/vibecode.md` dispatches on `$ARGUMENTS`. `hooks/prompt_submit.py` handles `/vibecode` (init + active, or status), `off` and `terse` deterministically before the command file is read; `vibecode_init.init(repo)` is importable for that.

## Layout

- `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.codex-plugin/plugin.json`: manifests. Keep `version` identical in both plugin manifests.
- `commands/`: one thin command file.
- `hooks/`: `hooks.json` (Claude Code), `codex-hooks.json`, `session_start.py`, `prompt_submit.py`. Hooks read the ruleset from `skills/vibecode/SKILL.md` under the heading `## Active mode rules` and the voice from `skills/vibecode/references/terse.md` + `terse-upstream.md`; do not rename that heading or those files.
- `skills/vibecode/references/terse-upstream.md` is generated by `scripts/sync_terse.py` from JuliusBrussee/caveman (`skills/ultracave/SKILL.md`); never edit it by hand. `.github/workflows/sync-terse.yml` runs the sync weekly and commits to main when upstream changed and tests pass.
- `skills/`: `vibecode` (loop), `asking` (decision protocol), `prior-art` (search repository and community before building anything new; license gate), `understand` (history), `execution-slices` (scope gates), `review-i2b` (behavioral review). Each has `agents/openai.yaml` for Codex.
- `scripts/`: Python 3.9+ standard library. `vibecode_state.py` is imported by the others and by the hooks; keep it dependency-free.
- `contracts/`, `references/`, `templates/`: schemas, methodology, `STRUCTURE.md` template.
- `tests/`: `unittest`.
- `docs/legacy/`: unrelated historical notes (local OpenAI-compatible proxies). Not part of the plugin.

## Build, test, lint

- `python3 -m unittest discover tests`
- `python3 -m compileall -q scripts hooks`
- `git diff --check`

## Rules for changes here

- Skills reference scripts as `<plugin>/scripts/...`; in Claude Code `<plugin>` is `${CLAUDE_PLUGIN_ROOT}`, otherwise two directories above the SKILL.md.
- Scripts print one JSON object and use the exit codes documented in `README.md`; changing a code means updating the README table and the skill that interprets it.
- Hooks never raise, always exit 0, and must finish within 5 seconds.
- A feature that lets the agent decide more on its own does not belong here.

## Done means

Manifests parse, `unittest` passes, `compileall` passes, hooks answer the sample payloads in the README, and the plugin installs from a clean cache.
