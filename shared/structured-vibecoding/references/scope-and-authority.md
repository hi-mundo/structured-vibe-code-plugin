# Scope, authority, and checkpoints

The human owns product behavior, architecture, data contracts, persistence, security, observability, and irreversible choices. The agent discovers facts, exposes tradeoffs, critiques options, and implements the selected option.

A slice is one coherent behavior, contract, module, migration, or refactoring. File count never defines scope. Start only from a clean worktree; finish the behavior, validate it, review the diff, report risk, obtain explicit commit authorization, commit, and confirm a clean worktree before another slice. Never discard or silently absorb user changes.

Before implementation, record the selected architecture, rejected alternatives, module and symbol ownership, dependency direction, lifecycle/state ownership, complexity budget, and whether the correct result is a service, module, class, function, script, configuration, documentation, or no code.
